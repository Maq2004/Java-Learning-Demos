
在今天的学习数组的时候我发现了一个问题：为什么我声明了一个数组的长度是三，但是我可以用匿名数组的方式给他存进去五个数据结合前面学到的类的知识由此引发了我的三个疑问
1.长度的矛盾：为什么数组声明了长度却能给它赋更多的值？
2.引用的本质：为什么将一个数组名给另一个数组赋值后，用第一个数组名修改变量，第二个数组里的数据仍然会改变？
3.类型的差异：为什么int[]存的是数字，而User[]（自己创建的用户类）存完后还得用循环来创造实例才能使用。


第一阶段：打破长度不可变的认知
    由于我的第一门语言是c语言，而且学的并不够深入，所以数组在我的脑海里一直都是固定不能改变的，我将这个认知带到了Java中，但是我通过观察使用匿名数组arr = new int[]{1，2，3，4，5}可以给数组重新赋值，并且长度不受创建数组时的大小限制，为什么？继续搜索资料后我发现，Java数组名和C语言的数组名的本质的区别：
        在 Java 中，arr 只是一个存储在栈上的引用。
        当我写 new int[3] 时，我在堆里挖了一个 3 格的坑，遥控器对准了它。
        当我写 arr = new int[5] 时，我并不是把原来的 3 格坑扩建成 5 格，而是在堆里的另一个地方又挖了一个 5 格的新坑，并把遥控器的信号转向了新坑，而旧的小的数组并没有消失，只是变成了没人要的垃圾，等待被JVM回收。

悟到的点：
数组的长度确实不可变。但数组名的指向是自由的。所谓的“赋更多的值”，本质上是抛弃了旧的小房子，住进了更大的新房子。

第二阶段：数组名字的另一个用法
    在c语言中，数组名称有两个身份，一是代表整个数组如sizeof(a),二则是代表数组首元素的地址。并且用数组名给另一个数组赋值的时候，会直接报错，但是在Java中可以用一个数组名给另一个数组赋值，为什么？因为Java的数组设计，Java中的数组名并不同于C语言是个常量，它是个引用变量，当我写下int[] b = a;（a是数组名）的时候,内存中发生了什么？Java并没有搬动任何数组里的数字，他只是把a指向的地址给了b，这也就解释了为什么为什么将A数组给B数组赋值后，修改A数组中的变量B数组里的变量也会一同改变，根本的原因是因为他们指向同一块内存
    C 语言的数组名是常量（不可移动），Java 的数组名是变量（可以转手）。这就是为什么 Java 可以直接赋值，且赋值后会产生“连带修改”现象。 


第三阶段：为什么User[]还需要再走一步？
    我的第三个疑问，为什么 int[] 存完就能用，而 User[] 存完还得循环 new？因为int 是基本数据类型，它在内存中的大小是固定的（4 字节）。当我 new int[3] 时，JVM 在堆里直接开辟了 3 个 4 字节的格子，并在格子里填上了默认值 0。格子里已经有东西了，所以我直接 arr[0] 就能拿来用。而User 是一个类。当我执行 User[] users = new User[3]; 时，JVM 确实开辟了空间，但格子里存的不是“用户数据”，而是预留给另一个遥控器的位子。初始状态下，格子里全是 null。我只是开辟了一段内存空间用来存放指向实例的地址，但实例还没有被创建。我必须通过 for 循环，给每个格子 new User()。二跳寻址。
